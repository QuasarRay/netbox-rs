# netbox-rs

Rust tooling and generated protobuf contracts for the NetBox API.

The typed protobuf contracts under `proto/netbox/` are generated by `src/bin/netbox_openapi_proto.rs` from the committed NetBox OpenAPI snapshot at `openapi/openapi.json`.

A second Rust stage, `src/bin/netbox_openapi_fidelity.rs`, makes the generated protobuf set lossless. It emits protobuf custom-option definitions plus a source descriptor file containing the **exact original OpenAPI JSON bytes**, base64-chunked inside `google.protobuf.FileOptions`. The stage then reconstructs those bytes and refuses the output if the round trip differs.

This is necessary because OpenAPI semantics such as JSON Schema unions and constraints, media types, parameter serialization, security requirements, nullable/read-only/write-only behavior, callbacks, links, and arbitrary extension fields do not all have native protobuf equivalents. The typed protobuf messages remain the convenient projection; the embedded OpenAPI document is the authoritative lossless contract.

## Regenerate

```sh
cargo run --bin netbox_openapi_proto -- \
  --input openapi/openapi.json \
  --output-dir proto/netbox \
  --package netbox.v1

cargo run --bin netbox_openapi_fidelity -- \
  --input openapi/openapi.json \
  --output-dir proto/netbox \
  --package netbox.v1 \
  --verify-generated
```

## Verify fidelity sidecars without modifying files

```sh
cargo run --bin netbox_openapi_fidelity -- \
  --input openapi/openapi.json \
  --output-dir proto/netbox \
  --package netbox.v1 \
  --check \
  --verify-generated
```

CI generates into a temporary directory, verifies byte-for-byte OpenAPI reconstruction, and compiles the complete descriptor set with `protoc`. Once the committed protobuf tree has been migrated by a normal refresh, CI also enforces byte-for-byte reproducibility of all generated files.

OpenAPI is treated as the public API contract. NetBox models and migrations remain authoritative for persistence semantics.
